## 工作原则

- 先理解现有代码，再修改。
- 优先最小改动，不进行无关重构。
- 不随意添加新的依赖。
- 不修改未涉及任务的功能。
- 不删除已有兼容逻辑。
- 不确定的地方优先从项目文件中查找答案。
- 保持 TypeScript 类型完整。
- 所有接口必须包含错误处理。
- AI 返回结果必须经过 JSON 校验。
- 修改后运行类型检查和相关测试。

## 修改完成后必须汇报

每次任务完成后，输出：

1. 修改了什么
2. 修改了哪些文件
3. 为什么这样修改
4. 如何验证
5. 是否还有风险或未完成项

## 禁止事项

- 禁止伪造已运行的测试结果。
- 禁止声称代码可用但没有验证。
- 禁止未经说明改变 API 数据结构。
- 禁止一次性重写整个项目。
- 禁止把 mock 数据称为真实 API 数据。
